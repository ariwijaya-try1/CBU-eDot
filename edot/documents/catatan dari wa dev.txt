[5 Oktober 2026] Note dari dev eDot (WA) -- Fitur Stok Toko (Outlet Stock) LIVE di production, endpoint BARU POST /v1/webhook/store-stock (jawaban atas pertanyaan 29 September)

Halo tim Cahaya Boga Utama

Fitur Stok Toko (Outlet Stock) sudah live di production. ODOO sekarang bisa mengirim stok di toko/outlet customer. Datanya sama dengan yang diinput salesman di eWork, menu Outlet Detail -> Product Stock.

Endpoint
POST https://openapi-esuite.edot.id/v1/webhook/store-stock
Autentikasi sama dengan webhook lain yang sudah dipakai: header Authorization, X-Signature, X-Timestamp, dan X-Request-ID, dengan client ID & secret yang sama.

Contoh request
{
  "event": "upsert",
  "data": [
    {
      "customer": { "external_code": "ODOO-PARTNER-1655" },
      "product_variant": { "external_code": "ODOO-PROD-18374" },
      "uom_level_code": "",
      "on_hand": 12,
      "expired_date": "2026-12-31"
    }
  ]
}

Penjelasan field
* customer.external_code (wajib): kode customer/toko. Kalau toko belum punya gudang stok, sistem membuatkannya otomatis. Customer wajib punya sales branch.
* product_variant.external_code (wajib): kode produk.
* uom_level_code (opsional): kosongkan untuk memakai satuan dasar produk. Saat ini semua produk Cahaya hanya punya satu satuan, jadi cukup dikosongkan.
* on_hand (wajib, >= 0): jumlah stok akhir di toko, bukan selisih/penambahan. Nilai 0 artinya stok habis.
* expired_date (opsional, format YYYY-MM-DD): tanggal kedaluwarsa. Tanggal berbeda dicatat sebagai stok terpisah. Kosongkan kalau tidak ada tanggal kedaluwarsa.

Note:
- Maksimal 50 item per request. Data lebih dari itu perlu dipecah menjadi beberapa request yang dikirim berurutan.
- Nilai yang dikirim menimpa stok sebelumnya. Mengirim ulang data yang sama aman: stok tidak bertambah dua kali.
- Stok produk yang tidak dikirim tidak diubah, jadi tidak perlu mengirim seluruh stok toko sekaligus.
- Dalam satu request, kombinasi customer + produk + satuan + tanggal kedaluwarsa tidak boleh muncul dua kali.

Ringkasan (catatan Claude, bukan dari dev):
- Endpoint KHUSUS (bukan /stock-matrix). Target pakai customer.external_code -> 3 blocker 29 September (target warehouse.id, cara buat/link warehouse outlet, POST /warehouse outlet) GUGUR; warehouse outlet dibuat otomatis oleh eSuite.
- Prasyarat: customer sudah punya sales branch (mapping Customer -> Branch).
- on_hand = nilai akhir (menimpa). Kirim ulang on_hand 0 utk produk yang stoknya sudah diisi sales (tanpa expired) AKAN mereset isian sales.
- BELUM dijawab / belum dites: format response kalau sebagian item gagal; ada/tidaknya GET stok toko; perilaku app saat sales mengisi expired di baris placeholder (update baris atau baris baru); apakah baris on_hand 0 tampil di list Product Stock eWork; rate limit.
