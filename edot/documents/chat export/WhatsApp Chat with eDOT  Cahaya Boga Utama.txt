Halaman produk (tab Attribute & Variant) menampilkan varian dari field variants yang ter-embed di dalam dokumen product, bukan dari collection variant yang berdiri sendiri.

*Saat ini flow yang dipakai oleh pak Ari:*
Push /product (tanpa field variants), lalu
Push /product-variant terpisah.
Endpoint /product-variant terpisah hanya membuat record varian mandiri (makanya muncul di halaman "List All Variant"), tapi tidak menautkannya ke product.variants[] milik produk induk. Akibatnya di halaman produk variants-nya kosong → muncul tulisan "Input Data Attribute To Add Variant".

*Solusi*
Sertakan array variants langsung di dalam payload /product (tidak perlu push /product-variant terpisah). Contoh:


{
  "event": "upsert",
  "data": [{
    "external_code": "ODOO-PROD-9035",
    "name": "ACETAIA Pure Glaze 1x12x250mL",
    "status": "active",
    "product_type":     { "id": "664191ad236dfcd5a4000001" },
    "product_category": { "id": "01KZ5Q6FNTM3G8G7R3E2P3SHVT" },
    "base_uom":     { "id": "664219e2236dfcd5a400001a" },
    "purchase_uom": { "id": "664219e2236dfcd5a400001a" },
    "uom_levels": [{ "id": "01KZ5895R0T1JTR4QTVFGE3GHF", "uom": { "id": "664219e2236dfcd5a400001a" }, "qty": 1, "convertion": 1 }],
    "cost": 0,
    "base_price": 57670,
    "currency": { "id": "6a695cc1917e8fc836359505" },
    "variants": [
      {
        "id": "6a7d359c1a6a0f06f95ee16b",
        "name": "ACETAIA Pure Glaze 1x12x250mL",
        "external_code": "ODOO-PROD-9035",
        "attributes": [],
        "sku": "",
        "barcode": "",
        "cost": 0,
        "extra_price": 0,
        "status": "active"
      }
    ]
  }]
}
Yang perlu diperhatikan pada sisi sync ODOO:

Produk baru → cukup sertakan variants di payload create. Kalau variants[].id dikosongkan, eSuite akan generate id varian otomatis dan mengisi product.variants[] sekaligus. Simpan id tersebut di ODOO untuk update berikutnya.
Produk yang variannya sudah terlanjur dibuat (seperti ODOO-PROD-9035) → kirim ulang produk dengan variants[].id diisi id varian yang sudah ada (ambil dari GET /product-variant berdasarkan external_code). Ini akan menautkan varian tanpa membuat duplikat.
Kirim id varian yang konsisten setiap sinkronisasi. Matching varian saat update berdasarkan id, bukan external_code. Jika setiap cycle mengirim varian tanpa id, akan terbentuk varian duplikat tiap sync.
Hentikan push /product-variant terpisah untuk keperluan tampil di halaman produk — itu penyebab varian tidak muncul.
Catatan: attributes hanya diperlukan bila Anda ingin varian berbasis matriks atribut (mis. Size/Color). Untuk satu varian default, cukup kirim satu varian dengan attributes: [].

15/08/2026, 13:18 - Giovankov Edot: 1. Nilai bersifat set-to-target (absolut), bukan penjumlahan.
on_hand yang Anda kirim = nilai stok akhir yang diinginkan. Contoh: kirim on_hand: 100 → stok menjadi 100. Dikirim ulang dengan nilai sama → tidak berubah (idempotent). Untuk menurunkan, cukup kirim nilai lebih kecil (mis. 100 → 10).

2. Satu baris stok per kombinasi kunci — bukan per pengiriman.
Stock-matrix disimpan 1 baris per kombinasi: company + product_variant + uom + warehouse + location + batch.
Kirim berkali-kali ke kombinasi yang sama → memperbarui baris yang sama (tidak menduplikasi). GET akan tetap menampilkan 1 baris untuk kombinasi itu.
Jika mengirim ulang menggunakan warehouse berbeda (atau variant / uom / location / batch berbeda) → membuat baris baru untuk kombinasi tersebut, dengan stok yang dikelola terpisah.
Contoh: variant ODOO-PROD-19513 di ODOO-WH-1 dan di ODOO-WH-6 = 2 baris berbeda, masing-masing punya on_hand sendiri.
